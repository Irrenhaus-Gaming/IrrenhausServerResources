# Admin shop (EconomyShopGUI)

The EconomyShopGUI files under `Backend/plugins/EconomyShopGUI/sections/` and `shops/` are not stored in the repo. mcdeploy builds them from this folder whenever a backend is rendered: on deploy, in the boot test and with `mc render`. The folder `.gitignore`s them, and mcdeploy refuses them if they appear in the repo anyway.

| File | What it is |
|---|---|
| `items.yml` | the value of every base item, grouped by what the shop pays for it; excluded and held-back items; custom entries such as spawners |
| `layout.yml` | the menu: categories, sub-sections, which item goes where |
| `vanilla.lock.yml` | generated by `mc shop-audit` from the server jar: every item's rarity and max stack, the item tags, and the ingredients of every recipe. Do not edit it by hand |
| `../knobs.yml` → `shop` | the knobs that turn values into prices (markup, sell ratios, rarity premium, one global multiplier) |

## The rules

- **Value V** is the fair price of one item between players, in Moneten. The anchors are cobblestone 1, iron ingot 30 and diamond 500. The scale follows the quests: mining 640 stone pays 1,500.
- **The shop sells** at `V × markup × rarity premium` (rounded up) and **buys** at `V × sell ratio` (rounded down). With markup 2 and sell ratios of at most 0.3, the gap is at least 6×. Any price two players agree on in between beats the shop for both of them.
- **Farm output sells for token amounts.** Sell class `auto` (0.05) covers everything a farm makes without a player: iron golems, gold and piglin farms, raids, mob grinders, crops with observers, bone meal flowers, AFK fishing. A full iron farm therefore earns about 1.5 per ingot, not 30. This also keeps a spawner plugin that sells its loot at shop prices (SmartSpawner) harmless.
- **Crafted items are priced from their recipe.** An item without a value costs its ingredients × `craft_factor` (cheapest vanilla recipe), and sells for exactly what its ingredients would. Crafting never turns farm iron into a better-paying item, and an iron block always costs 9 ingots.
- **Lint enforces the rules on the rounded prices:**
  - buy ≥ 1.5 × V, sell ≤ 0.35 × V, and buy ≥ 3 × sell;
  - no vanilla recipe turns shop-bought ingredients into something that sells back for more;
  - no vanilla recipe (smelting included) turns items into something the shop pays more for than for the items themselves (upcraft). Farm output and spawner loot sold by hand therefore earn no more than sold as they are. A crafted item sells for what its ingredients sell for along its cheapest route; an item with its own value needs the same sell class as what it is made of (raw ore is worth its ingot).
- **Not offered:**
  - Unpriced items (no value, no priceable recipe) are not in the shop at all.
  - `exclude` items are never priced.
  - `held_back` items are priced but neither bought nor sold, and neither is anything crafted from them (elytra, netherite, shulker boxes, totems…). The endgame offer will be decided later.
  - Enchanted books are excluded so villager trading halls matter.
- **Bundles:** Moneten have no decimals, so cheap items are traded in bundles (`stack-size` up to the item's max stack). The bundle size keeps the rounding small; prices are per bundle.

## Spawners (SmartSpawner)

- **Bought here:** the `spawner_*` entries under `custom:` in `items.yml`, in the main menu's Spawner button (`layout.yml`). EconomyShopGUI hands them out as SmartSpawner spawners (`spawner-provider: SMART_SPAWNER`). Class `none`: the shop never buys a spawner back. Dungeon spawners can also be mined with Silk Touch.
- **Loot is sold at these prices:** SmartSpawner's sell button asks EconomyShopGUI for each item's sell price per item (sell / stack-size). `sell_integration.yml` must stay on `SHOP_ONLY` with custom prices off, otherwise SmartSpawner falls back to its own price list whenever the shop pays nothing.
- **Income cap:** lint computes what one spawner of every type earns per hour while a player is in range: `3600 / delay × (min_mobs + max_mobs) / 2 × Σ chance × average amount × sell per item`. It fails above `shop.spawner_income_cap` in `knobs.yml`. A stack of N spawners (up to `max_stack_size`) earns N times that.
- **Selling loot by hand** (`/sellall`, the shop menu) pays the same per item as SmartSpawner's sell button, so the cap covers both routes. Crafting or smelting the loot first can't raise it either (upcraft rule above).
- **Over the cap:** lower the chances of that mob's sellable loot in `spawner_mobs.yml` (the trimmed mobs carry a comment with their factor). Don't raise the cap or a sell price to make a spawner fit.
- `mc shop-report` lists every spawner's income and the payback time of the ones sold here. Item spawners (`spawner_items.yml`) are not allowed.

## Changing prices

1. Edit a value in `items.yml`, a knob in `knobs.yml`, or `layout.yml`.
2. Run `mc lint`, which checks the rules, and `mc shop-report`, which writes `.cache/out/shop-report.md`: every price per category plus the held-back items. CI adds the same table to the run summary.
3. Merge. The deploy uploads the shop files that changed. Run `/sreload` in game afterwards.

In-game shop editing (`/editshop`) is switched off. A server-side change to a deployed shop file is drift and aborts the deploy; `pull` refuses to bring it back and points here.

## After a Minecraft update

Run `mc shop-audit mc-backend-<Name> --jars-from remote`. It reads the new server jar with Mojang's data generator (in Docker), rewrites `vanilla.lock.yml`, and lists:
- new and removed items;
- changed rarities and stack sizes;
- every item that still has no price.

Give new base items a value in `items.yml`. Crafted ones price themselves.

## First deploy

The server still has the plugin's stock `sections/` and `shops/` files. A generated file that was never deployed replaces the server's copy without counting as drift. `retired` in `layout.yml` lists the stock sections this layout doesn't reuse, and each of them is deployed as a disabled section.
